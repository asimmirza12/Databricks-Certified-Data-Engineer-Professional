Unity Catalog functions

A function saved in Unity Catalog is like a table: it has a three-part name, an owner, permissions and lineage. Anyone you grant can call it from SQL or Python, on any compute that supports it.

The idea

The idea in plain English

A Unity Catalog function is a user-defined function stored permanently in a schema, named catalog.schema.function. Unlike a temporary function or spark.udf.register, it survives the session and can be shared.

It is a securable: an object Unity Catalog controls access to. To call it, a user needs USE CATALOG, USE SCHEMA and EXECUTE on the function. To create one, they need CREATE FUNCTION on the schema.

There are three common kinds:

  • SQL functions: the body is a SQL expression (or a query, for a function that returns a table). Fast, because the engine inlines them.
  • Python functions: the body is Python, written between $$ markers. They run in an isolated, sandboxed Python environment. Extra libraries are declared in an ENVIRONMENT clause.
  • Batch Python functions: Python functions with PARAMETER STYLE PANDAS and a HANDLER, which receive iterators of pandas Series, like the pandas UDFs of lesson 01-06. Much faster than row-at-a-time Python for large data.

Because they live in Unity Catalog, these functions are discoverable in Catalog Explorer, appear in lineage, and can be used inside row filters and column masks (module 06).

A temporary function is a sticky note on your own monitor. A Unity Catalog function is a procedure filed in the company handbook: it has a title and an owner, anyone with clearance can look it up and follow it, and the handbook records who used it.

Code

In code

A SQL function and a table function, shared with a group:

-- Scalar SQL function
CREATE OR REPLACE FUNCTION bike_shop.silver.price_band(minutes INT)
  RETURNS STRING
  COMMENT 'short / medium / long by ride length'
  RETURN CASE WHEN minutes < 15 THEN 'short' WHEN minutes < 45 THEN 'medium' ELSE 'long' END;

-- SQL table function: returns rows, used in FROM
CREATE OR REPLACE FUNCTION bike_shop.gold.rides_in_town(t STRING)
  RETURNS TABLE (ride_id STRING, price DECIMAL(8,2))
  RETURN SELECT ride_id, price FROM bike_shop.silver.rides WHERE town = t;

SELECT * FROM bike_shop.gold.rides_in_town('Riverside');

-- Share: callers need USE CATALOG, USE SCHEMA and EXECUTE
GRANT EXECUTE ON FUNCTION bike_shop.silver.price_band TO `analysts`;

A Python function with a library dependency:

CREATE OR REPLACE FUNCTION bike_shop.silver.station_slug(name STRING)
  RETURNS STRING
  LANGUAGE PYTHON
  ENVIRONMENT (
    dependencies = '["python-slugify==8.0.4"]',
    environment_version = 'None'            -- required with ENVIRONMENT; check the docs for current values
  )
  AS $$
    from slugify import slugify
    return None if name is None else slugify(name)
  $$;

A batch Python function: pandas Series in, pandas Series out, for big data:

CREATE OR REPLACE FUNCTION bike_shop.silver.km_from_miles(miles DOUBLE)
  RETURNS DOUBLE
  LANGUAGE PYTHON
  PARAMETER STYLE PANDAS
  HANDLER 'convert'
  AS $$
    import pandas as pd
    from typing import Iterator
    def convert(batches: Iterator[pd.Series]) -> Iterator[pd.Series]:
        for miles in batches:
            yield miles * 1.60934
  $$;
# Call any of them from Python too
spark.sql("SELECT ride_id, bike_shop.silver.price_band(minutes) AS band FROM bike_shop.silver.rides")

The environment_version value and supported compute change over time. Check the "SQL and Python UDFs in Unity Catalog" page before relying on a specific value (verify in the docs).

Options

What if I change this?

ChangeEffect
Grant EXECUTE but not USE SCHEMACalls still fail. Like tables, functions need the parent USE privileges too.
Add an ENVIRONMENT clause with dependenciesThe function installs those packages (PyPI, volume wheels or URLs) in its own isolated environment. environment_version becomes required.
Dependency wheel stored in a volumeDepending on the environment version, callers may also need READ VOLUME on that volume (verify for your version).
Native wheel built for only one CPU typeServerless can run on x86_64 or ARM (aarch64), so it can fail. Provide both, marked with platform_machine.
Row-at-a-time Python → PARAMETER STYLE PANDASData arrives in pandas batches; much faster on large tables. Needs a HANDLER.
CREATE OR REPLACE an existing functionAll callers get the new logic immediately. Treat it like changing a shared table: test first.

Exam traps

Exam traps and look-alikes

Trap

"Register it with spark.udf.register so the whole team can use it." No: that lasts one session. Sharing needs a Unity Catalog function.

Trap

When the constraint is "only SQL logic, fastest, shared", the answer is a SQL UC function, not Python.

Don't confuse

EXECUTE (call a function) vs SELECT (read a table or view). Functions don't use SELECT.

Don't confuse

Batch UC Python function (PARAMETER STYLE PANDAS, stored in UC) vs a pandas UDF (@pandas_udf, session-scoped in your code).

Check yourself

Quiz

1. Analysts must call your cleaning logic from dashboards on a SQL warehouse. The logic is a CASE expression. Best choice?

It must be permanent and shareable, and SQL-only logic is fastest as a SQL function. Session functions vanish and can't be granted.

2. Which privileges let a group call bike_shop.silver.price_band?

Functions use EXECUTE, and like every securable they also need the parent USE privileges.

3. A UC Python function needs the python-slugify package. How do you provide it?

UC Python functions run in their own isolated environment, with dependencies declared in ENVIRONMENT.

4. A UC Python function is too slow on a 500-million-row table. Which change helps most?

Batch UC Python functions receive iterators of pandas Series, avoiding row-by-row overhead.

Wrap-up

Key takeaways

  • UC functions are permanent securables: catalog.schema.function, owner, grants, lineage.
  • Callers need USE CATALOG + USE SCHEMA + EXECUTE.
  • SQL functions are fastest; Python functions add libraries via ENVIRONMENT; batch Python (PARAMETER STYLE PANDAS) suits big data.
  • Session UDFs can't be shared; pick UC functions when others or SQL warehouses need the logic.
