Streaming ingestion with Auto Loader in pipelines

Files keep landing in cloud storage, and their shape changes when apps change. Auto Loader picks up each new file exactly once and decides what to do with surprises. Inside a pipeline, most of its plumbing is handled for you.

The idea

The idea in plain English

Auto Loader is a streaming source, named cloudFiles, that watches a cloud storage path and processes each new file once. It remembers processed files in the stream's checkpoint, so re-runs never load a file twice. In SQL, STREAM read_files(...) uses Auto Loader under the hood.

It can also work out the columns for you: schema inference. It samples files, writes the inferred schema to a schema location, and keeps it up to date. By default it infers every JSON and CSV column as a string; set cloudFiles.inferColumnTypes to true to get numbers and dates, or give schema hints for specific columns.

When a file brings a new column, the schema evolution mode decides what happens:

  • addNewColumns (default without a given schema): add the column. The stream stops once with an error, saves the new schema, and works after a restart. A pipeline restarts it for you.
  • rescue: never change the schema and never fail. Unknown data goes into the rescued data column (_rescued_data) as JSON.
  • failOnNewColumns: fail and stay failed until someone updates the schema.
  • none (default when you provide a schema): ignore new columns; nothing is rescued unless you ask for a rescued data column.

Inside a Lakeflow pipeline you don't set a checkpoint or schema location: the pipeline manages both.

Auto Loader is a post-room clerk with a logbook. Every new parcel is opened once and ticked off, so no parcel is handled twice. When a parcel arrives with an unexpected extra item, the clerk's instructions say whether to add a new shelf (add columns), put the item in a "found items" tray (rescue), stop and call the manager (fail), or ignore it (none).

Code

In code

SQL in a pipeline: options go into read_files.

CREATE OR REFRESH STREAMING TABLE rides_bronze
COMMENT 'Raw ride events, one row per JSON record'
AS SELECT
  *,
  _metadata.file_path              AS source_file,
  _metadata.file_modification_time AS file_time
FROM STREAM read_files(
  '/Volumes/bike_shop/raw/landing/rides/',
  format => 'json',
  schemaHints => 'price DECIMAL(8,2), started_at TIMESTAMP',
  schemaEvolutionMode => 'addNewColumns'
);

Python in a pipeline: no checkpoint or schema location needed.

from pyspark import pipelines as dp
from pyspark.sql import functions as F

@dp.table(comment="Raw ride events")
def rides_bronze():
    return (spark.readStream.format("cloudFiles")
        .option("cloudFiles.format", "json")
        .option("cloudFiles.inferColumnTypes", "true")          # else every column is a string
        .option("cloudFiles.schemaHints", "price DECIMAL(8,2)")
        .option("cloudFiles.schemaEvolutionMode", "rescue")      # never break; keep surprises
        .load("/Volumes/bike_shop/raw/landing/rides/")
        .withColumn("source_file", F.col("_metadata.file_path")))

Outside a pipeline, the same source needs two paths you manage yourself (module 02 covers this fully):

(spark.readStream.format("cloudFiles")
   .option("cloudFiles.format", "json")
   .option("cloudFiles.schemaLocation", "/Volumes/bike_shop/raw/_schemas/rides")
   .load("/Volumes/bike_shop/raw/landing/rides/")
 .writeStream
   .option("checkpointLocation", "/Volumes/bike_shop/raw/_checkpoints/rides")
   .trigger(availableNow=True)
   .toTable("bike_shop.bronze.rides"))

Options

What if I change this?

ChangeEffect
schemaEvolutionMode = addNewColumnsNew column added; the stream fails once, then works after restart. Pipelines (and jobs with retries) restart automatically.
schemaEvolutionMode = rescueSchema frozen; new or mistyped fields land in _rescued_data. The stream never stops for schema changes.
schemaEvolutionMode = failOnNewColumnsStops and stays stopped until the schema is updated by hand. Strictest.
schemaEvolutionMode = noneNew columns silently ignored. Add rescuedDataColumn if you want to keep them.
inferColumnTypes false (default)JSON/CSV columns become strings. Safe, but you must cast later.
schemaHintsFix the type of named columns while letting the rest be inferred.
includeExistingFiles = falseFiles already in the path when the stream first starts are skipped. Only checked on the very first run.
cloudFiles.maxFilesPerTriggerCaps files per micro-batch (1,000 by default; verify in the docs) to keep batches a manageable size.
cloudFiles.useManagedFileEvents = trueDiscover new files from Unity Catalog file events instead of listing the directory. Needs an external location with file events enabled.

Exam traps

Exam traps and look-alikes

Trap

The addNewColumns "failure" is expected: the stream stops once to save the new schema. The fix is automatic restart (pipeline or job retries), not changing modes.

Trap

In a pipeline, answers that set checkpointLocation or schemaLocation by hand are unnecessary: the pipeline manages them.

Don't confuse

Auto Loader (cloudFiles, streaming, incremental, exactly-once) vs COPY INTO (SQL batch command, also idempotent, fewer schema features; module 02).

Don't confuse

Rescued data column (keeps unexpected values per row) vs schema evolution (changes the table's columns).

Check yourself

Quiz

1. Bronze ingestion must never stop for schema changes, but no data may be lost. Which mode?

rescue never changes the schema or fails, and keeps unknown data in _rescued_data.

2. With addNewColumns, a new column arrives. What happens?

That one-off failure is by design. Pipelines and jobs with retries restart it automatically.

3. Auto Loader infers a JSON price column as STRING. Why?

Default inference is conservative. Turn on inferColumnTypes or give schemaHints.

4. In a Lakeflow pipeline, where do you set the Auto Loader checkpoint location?

Pipelines manage both for each streaming table.

Wrap-up

Key takeaways

  • Auto Loader (cloudFiles / STREAM read_files) processes each new file exactly once.
  • Evolution modes: addNewColumns (fail once, restart), rescue (never fail, keep extras), failOnNewColumns (stop), none (ignore).
  • JSON/CSV infer as strings unless inferColumnTypes or schemaHints say otherwise.
  • In pipelines, checkpoints and schema locations are managed for you; file events speed discovery.
