The idea

The idea in plain English

Compute means the machines that run your code. On Databricks there are three main families:

  • Serverless compute: you just run code; Databricks picks, starts and scales the machines in its own cloud account. It starts in seconds. Available for notebooks, jobs, pipelines and SQL. For most new work, Databricks recommends it.
  • Classic compute (a cluster you configure): you choose the machine types, number of workers and software version. It runs in your cloud account and takes a few minutes to start. Two flavours: all-purpose compute for interactive notebooks, and jobs compute, created for one job run and shut down after.
  • SQL warehouses: compute that only runs SQL, built for dashboards and queries. Types are serverless, pro and classic.

Databricks bills compute in DBUs (Databricks Units): a measure of processing power used per hour. Different compute types charge different DBU rates, and on classic compute you also pay your cloud provider for the machines.

On a classic cluster, the software version is the Databricks Runtime (Spark plus libraries; "LTS" versions get long-term support). Who may share the cluster is the access mode: Standard (formerly Shared) lets many users share it safely; Dedicated (formerly Single user) belongs to one user or group.

Getting around a city. Serverless is a taxi: wave, ride, pay for the trip. Classic all-purpose is owning a car: set it up how you like, but it costs money while parked unless you switch it off. Jobs compute is a rental for one trip, returned straight after. A SQL warehouse is a bus route built for one job: carrying lots of short SQL trips.

Code

In code

You usually create compute in the UI. Behind the scenes it is a small JSON definition, which you will later keep in bundles (module 01). A classic all-purpose cluster:

{
  "cluster_name": "analyst-exploration",
  "spark_version": "<an LTS Databricks Runtime version>",
  "node_type_id": "<a machine type from your cloud>",
  "autoscale": { "min_workers": 2, "max_workers": 8 },
  "autotermination_minutes": 30,
  "data_security_mode": "USER_ISOLATION"
}

USER_ISOLATION is the API value for Standard access mode (verify in the docs, as API names change less often than UI names).

A job task on serverless needs no cluster definition at all. In a bundle it looks like this (no new_cluster block):

resources:
  jobs:
    nightly_rides:
      tasks:
        - task_key: clean_rides
          notebook_task:
            notebook_path: ../src/clean_rides.ipynb
          # no cluster settings: the task runs on serverless compute
-- On a SQL warehouse, you just write SQL

Options

What if I change this?

ChangeEffect
Auto-termination shorter (e.g. 10 min)Less idle billing, but users wait for a restart after a coffee break (classic start-up takes minutes).
Auto-termination offThe cluster bills all night and all weekend until someone stops it.
Autoscaling instead of a fixed sizeWorkers follow the load between min and max: cheaper when quiet, faster when busy.
Run a scheduled job on all-purpose computeWorks, but all-purpose usually has a higher DBU rate and stays on between runs. Use jobs compute or serverless.
Standard access mode → DedicatedNeeded for some features (such as R, RDD APIs, GPU ML runtimes); the cluster is then tied to one user or group.
Classic → serverlessNo sizing or start-up wait; Databricks manages scaling. Some features and settings aren't available on serverless (module 01).
Turn on PhotonA faster engine for SQL and DataFrame work; it can change the DBU rate. Check whether your workload benefits.

Exam traps

Exam traps and look-alikes

Trap

Scheduling production jobs on an all-purpose cluster is a classic wrong answer. Prefer jobs compute or serverless for scheduled work.

Trap

Old names: "Shared" access mode is now Standard; "Single user" is now Dedicated. Questions may use either.

Don't confuse

Autoscaling (changes the number of workers while running) vs auto-termination (shuts the whole cluster down after idle time).

Don't confuse

SQL warehouse (SQL-only compute for queries and BI) vs cluster (general Spark compute for any language).

Check yourself

Quiz

1. A nightly ETL notebook runs for 10 minutes. Which compute is the poorest choice?

An always-on all-purpose cluster bills between runs and usually at a higher rate. Jobs compute and serverless only run when the job does.

2. What does auto-termination do?

Auto-termination stops an idle cluster so it stops billing. Removing workers under low load is autoscaling.

3. Which compute is built only for SQL queries and dashboards?

SQL warehouses run SQL only and are tuned for many short queries from BI tools.

4. "Single user" access mode is now called…

Single user became Dedicated; Shared became Standard.

Wrap-up

Key takeaways

  • Three families: serverless (managed, starts fast), classic clusters (you configure), SQL warehouses (SQL only).
  • Scheduled work belongs on jobs compute or serverless, not all-purpose clusters.
  • Autoscaling fits workers to load; auto-termination stops idle clusters billing.
  • Access modes: Standard (formerly Shared) and Dedicated (formerly Single user).
