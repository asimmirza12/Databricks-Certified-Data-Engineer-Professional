The idea

The idea in plain English

A DataFrame is Spark's version of a table inside your program: rows and named, typed columns. It is not the data itself. It is a recipe that says where the data comes from and which steps to apply. (That is the laziness from lesson 00-05.)

You can build the recipe two ways:

  • The DataFrame API: Python methods chained together, like rides.filter(...).groupBy(...). In Python this is PySpark.
  • Spark SQL: ordinary SQL text, like SELECT ... FROM rides WHERE ....

Both go through the same optimizer (Spark's planner, called Catalyst), which rewrites your recipe into the fastest plan it can find. So the same question gives the same plan and the same speed in either language. Pick whichever reads better for the job, and mix them freely.

To use a DataFrame from SQL, give it a temporary name with a temporary view. To use SQL from Python, call spark.sql(...); it returns a DataFrame.

Ordering coffee: you can tick boxes on a form (the DataFrame API) or say "large oat latte, extra shot" to the barista (SQL). Both orders reach the same espresso machine (the optimizer) and you get the same coffee, made the same way.

Code

In code

The everyday DataFrame operations:

from pyspark.sql import functions as F

rides = spark.read.table("bike_shop.silver.rides")

result = (rides
  .select("ride_id", "town", "minutes", "price")                     # keep some columns
  .where(F.col("town") == "Riverside")                              # keep some rows (filter = where)
  .withColumn("price_per_min", F.round(F.col("price") / F.col("minutes"), 2))  # add a column
  .orderBy(F.col("price").desc()))                                # sort

display(result)    # Databricks notebook helper: shows a table (and is an action)

Switching between the two languages:

# Python -> SQL: give the DataFrame a temporary name for this session
result.createOrReplaceTempView("riverside_rides")

# SQL -> Python: spark.sql returns a DataFrame you can keep chaining
top = spark.sql("""
  SELECT town, COUNT(*) AS rides, SUM(price) AS revenue
  FROM riverside_rides
  GROUP BY town
""")
top.printSchema()   # columns and types of the result
-- In a Databricks notebook, a cell starting with %sql runs SQL directly
-- %sql
SELECT town, ROUND(AVG(price), 2) AS avg_price
FROM bike_shop.silver.rides
GROUP BY town
ORDER BY avg_price DESC;

Options

What if I change this?

ChangeEffect
Write the same query in SQL instead of PySparkSame plan, same speed. Only readability changes.
createOrReplaceTempViewA name for SQL, visible only in your current Spark session. Gone when the session ends; nothing is saved.
saveAsTable instead of a temp viewData is written as a real table that others can query later.
withColumn using a name that already existsReplaces that column instead of adding a new one.
Refer to a column that doesn't existAn error when Spark analyses the plan, before any data is read.
Call withColumn hundreds of times in a loopThe plan grows huge and slow to optimise. Build the columns in one select instead.

Exam traps

Exam traps and look-alikes

Trap

"SQL is slower than PySpark" (or the reverse). Both compile to the same optimised plan. Answers built on this claim are wrong.

Trap

A temporary view stores no data and disappears with the session. If something must survive or be shared, it needs a table (or a permanent view).

Don't confuse

filter and where on a DataFrame are the same thing; two names for one method.

Don't confuse

A Spark DataFrame (lazy, distributed, a plan) vs a pandas DataFrame (in memory on one machine, computed immediately). Module 01 mixes them in pandas UDFs.

Check yourself

Quiz

1. The same aggregation is written once in PySpark and once in SQL. How do they compare?

Both languages are front ends to the same optimizer, so equivalent queries become the same physical plan.

2. How do you query a Python DataFrame with SQL?

A temporary view gives the DataFrame a name that SQL in the same session can use.

3. What does spark.sql("SELECT ...") return?

It returns a DataFrame, so you can keep chaining PySpark methods on the result.

4. You create a temp view in notebook A. A teammate's notebook B can't see it. Why?

Temporary views are session-scoped. To share, write a table or create a permanent view.

Wrap-up

Key takeaways

  • A DataFrame is a lazy, distributed table in your program: a recipe, not stored data.
  • The DataFrame API and Spark SQL share one optimizer, so equivalent queries perform the same.
  • Temp views let SQL use a DataFrame; spark.sql lets Python use SQL.
  • Everyday verbs: select, where, withColumn, groupBy/agg, orderBy, join.
