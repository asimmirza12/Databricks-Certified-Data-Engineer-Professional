Reference

Glossary

Every term the course uses, in plain words. Lessons link here the first time a term appears. More terms are added as each module is built.

Access mode
A classic compute setting for who can share it. Standard (formerly Shared) or Dedicated (formerly Single user). Lesson 00-09.
ACID
Atomic, consistent, isolated, durable: the promises that writes fully happen or not at all and readers never see half-done work. Lesson 00-10.
Action
A Spark command that needs a real result, such as count(), display() or a write. It makes Spark run the plan. Lesson 00-05.
Aggregation
Combining many rows into summary values, such as a sum or count per group. Lesson 00-12.
All-purpose compute
A classic cluster for interactive work that many notebooks can attach to. Not meant for scheduled jobs. Lesson 00-09.
Auto-termination
Shutting down a classic cluster automatically after a set time with no activity, to stop billing. Lesson 00-09.
Autoscaling
Adding or removing workers automatically between a minimum and maximum as the workload changes. Lesson 00-09.
availableNow
A streaming trigger that processes all data that is new since the checkpoint, then stops. Used for scheduled incremental jobs; replaced Trigger.Once. Lesson 00-04.
Avro
A compact, binary, row-based file format that stores its schema with the data. Common for messages on Kafka. Lesson 00-03.
Batch processing
Processing a chunk of collected data in one run, usually on a schedule. Lesson 00-04.
Bronze layer
The raw layer of the medallion architecture: data as it arrived, plus source details. Lesson 00-12.
Bucket
A top-level container in cloud object storage that holds objects. Azure calls it a container. Lesson 00-07.
Catalog
The first level inside a Unity Catalog metastore. Holds schemas. Lesson 00-11.
Catalyst optimizer
Spark's query planner. It turns DataFrame or SQL code into an efficient physical plan. Lesson 00-06.
Cell
One block of code or text in a notebook, run on its own. Lesson 00-08.
Checkpoint
A folder where a streaming query records what it has already processed, so it can restart where it stopped. Lesson 00-04.
Classic compute
Compute you configure (machine types, workers, runtime) that runs in your own cloud account. Lesson 00-09.
Cloud object storage
Rented, nearly unlimited storage from a cloud provider (Amazon S3, Azure Data Lake Storage, Google Cloud Storage). Holds objects found by key. Lesson 00-07.
Cluster
A group of computers working together. In Spark: one driver plus executors. Lesson 00-05.
Column
One named fact stored for every row of a table, such as price. Has a data type. Lesson 00-02.
Columnar format
A file layout that stores all values of one column together. Fast for analytics, compresses well. Parquet is columnar. Lesson 00-03.
Commit
One recorded change to a Delta table, written as a numbered file in the transaction log. Creates a new version. Lesson 00-10.
Compression
Storing data in fewer bytes by encoding repeated patterns. Columnar files compress especially well. Lesson 00-03.
Compute
The machines that run your code: serverless compute, classic clusters or SQL warehouses. Lesson 00-09.
Compute plane
Where Databricks processes data: serverless (in Databricks' account) or classic (in your cloud account). Lesson 00-08.
Consumer
Anyone or anything that uses the output of a pipeline: a dashboard, an analyst, a model, an app. Lesson 00-01.
Control plane
The Databricks-run back end: web app, notebook storage, job scheduler and other services. Lesson 00-08.
Core
One processor inside a machine. In Spark, each core runs one task at a time. Lesson 00-05.
Credential
A secret, such as a cloud role or key, that proves you may access something. Unity Catalog stores storage credentials so users never handle them. Lesson 00-07.
CSV (comma-separated values)
A plain-text, row-based format: one line per row, values split by commas. No types or schema inside. Lesson 00-03.
Data engineering
The work of moving data from where it is created to where people use it, and making it clean and reliable along the way. Lesson 00-01.
Data pipeline
A repeatable series of steps that takes data from sources, changes it, and saves the result. Usually runs on a schedule or continuously. Lesson 00-01.
Data quality
How far you can trust data: is it complete, correct, on time and free of duplicates? Pipelines add checks on purpose to protect it. Lesson 00-01.
Databricks
A cloud platform for data engineering, analytics and AI, built on Apache Spark and open table formats. Lesson 00-08.
Databricks Runtime
The software image on classic compute: Spark plus libraries. LTS versions get long-term support. Lesson 00-09.
DataFrame
Spark's table-like object in code: named, typed columns over distributed rows. Lazy: it describes work rather than holding results. Lesson 00-06.
DataFrame API
The set of methods (select, where, groupBy…) used to build DataFrame queries in Python, Scala or R. Lesson 00-06.
DBFS mount
An old way to attach cloud storage to a Databricks path like /mnt/…. Deprecated: it bypasses Unity Catalog and doesn't work on serverless. Lesson 00-07.
DBU (Databricks Unit)
The unit Databricks uses to measure and bill processing per hour. Rates differ by compute type. Lesson 00-09.
Delta Lake
An open table format: Parquet data files plus a transaction log. The default table format on Databricks. Lesson 00-03; more in 00-10.
Driver
The coordinating process in a Spark cluster. It plans work and hands tasks to executors. Lesson 00-05.
ELT (extract, load, transform)
A pipeline order where raw data is saved first and cleaned later, inside the data platform. Keeps a raw copy for re-processing. Lesson 00-01.
ETL (extract, transform, load)
A pipeline order where data is copied out of a source, cleaned and reshaped, then saved for use. Lesson 00-01.
Event
A small record of something that happened at a point in time, like "bike 7 unlocked at 09:14". Lesson 00-04.
Executor
A worker process in a Spark cluster that runs tasks on partitions of data. On Databricks, one per worker machine. Lesson 00-05.
External table
A Unity Catalog table whose files live at a storage path you manage. Dropping it leaves the files. Lesson 00-11.
File
A named chunk of bytes saved in storage. The computer stores it without knowing what is inside. Lesson 00-02.
File format
The agreed layout of bytes inside a file, such as CSV, JSON or Parquet. Lesson 00-03.
File skipping
Not opening files whose stored statistics (like min and max values) prove they can't match a query. Also called data skipping. Lesson 00-03.
Folder (directory)
A named container that groups files in storage. Lesson 00-02.
Gold layer
The business-ready layer of the medallion architecture, often aggregated for a purpose. Lesson 00-12.
Governance
Controlling who can see and change data, and keeping a record of it. Lesson 00-11.
Apache Iceberg
An open table format: Parquet data files plus metadata files. Supported on Databricks with USING ICEBERG. Lesson 00-03.
Idempotent
Safe to repeat: running it again on the same input gives the same result, with no duplicates. Lesson 00-01.
Incremental processing
Processing only data that is new since the last run, instead of everything again. Lesson 00-04.
Jobs compute
A classic cluster created for one job run and shut down when it finishes. Lesson 00-09.
JSON
A text, row-based format where each record lists field names and values, and can nest. Common for app events and APIs. Lesson 00-03.
Key (object storage)
The full name of an object, such as rides/2026/11/19/a.json. Slashes are just characters. Lesson 00-07.
Lakehouse
Keeping all data in low-cost object storage, in open table formats, with warehouse-style reliability and governance on top. Lesson 00-08.
Latency
The delay between something happening and its data being available to use. Lesson 00-04.
Lazy evaluation
Spark records transformations in a plan and runs nothing until an action asks for a result. Lesson 00-05.
Magic command
A notebook cell prefix starting with %, such as %sql, %md, %pip or %run, that changes what the cell does. Lesson 00-08.
Managed table
A Unity Catalog table whose storage Unity Catalog chooses and maintains. Dropping it deletes the data after a recovery window. The default. Lesson 00-11.
Medallion architecture
Organising lakehouse tables into bronze (raw), silver (clean) and gold (business-ready) layers. Lesson 00-12.
Metadata
Data about data, such as a table's name, schema and list of files. Lesson 00-02.
Metastore
The top of Unity Catalog's tree, one per cloud region, holding catalogs. Lesson 00-11.
Micro-batch
A very small batch of new data. Spark streaming runs one micro-batch after another. Lesson 00-04.
Notebook
A web document of cells holding code (Python, SQL, Scala, R) or text, run interactively. Lesson 00-08.
Notebook state
Variables, temp views and installed libraries held in memory for a notebook. Lost when compute detaches or restarts. Lesson 00-08.
NULL
A marker meaning "no value here". Not zero and not an empty string. Lesson 00-02.
Object
A file stored in object storage, plus a little metadata. Written and replaced whole, never edited in place. Lesson 00-07.
OPTIMIZE
A Delta command that rewrites many small files into fewer, larger ones. Lesson 00-10; more in module 05.
Parquet
A binary, columnar, compressed file format that stores its schema. The data files inside Delta and Iceberg tables. Lesson 00-03.
Partition (Spark)
A chunk of a DataFrame's rows that one task processes. Not the same as a table partition (module 05). Lesson 00-05.
Photon
Databricks' fast native query engine for SQL and DataFrame work. Lesson 00-09.
Prefix
The start of an object key. Tools show keys with a shared prefix as a "folder". Lesson 00-07.
Privilege
A permission granted on a Unity Catalog object, such as USE CATALOG, USE SCHEMA or SELECT. Lesson 00-11.
PySpark
The Python library for working with Apache Spark, the engine that processes data on Databricks. Lessons 00-01, 00-06.
Query
A question you ask a table, usually written in SQL, such as "what was total revenue last week?". The answer comes back as rows. Lesson 00-01.
RESTORE
A Delta command that makes an older version current again, by adding a new commit. Lesson 00-10.
Row
One record in a table, such as one ride. Lesson 00-02.
Row-based format
A file layout that stores each record's values together, one record after another. CSV, JSON and Avro. Lesson 00-03.
Schema (of a table)
The list of a table's columns and each column's data type. Not the same as a Unity Catalog schema, which is a container (lesson 00-11). Lesson 00-02.
Schema (Unity Catalog)
A container inside a catalog that holds tables, views, volumes and functions. Also called a database. Lesson 00-11.
Schema enforcement
A table rejecting writes whose columns or types don't fit its schema. Lesson 00-02.
Schema evolution
Changing a table's schema to accept new data, for example adding a column with mergeSchema. Opt-in. Lesson 00-02.
Schema-on-read
Working out data's structure when reading it, not when storing it. Lesson 00-02.
Schema-on-write
Fixing the structure first and only accepting data that matches it. How tables work. Lesson 00-02.
Serverless compute
Compute that Databricks starts, sizes and manages for you in its own account. Starts in seconds. Lesson 00-09.
Shuffle
Moving rows between executors so rows with the same key end up together, for example for a group-by or join. Often the slowest step. Lesson 00-05.
Silver layer
The cleaned, de-duplicated, validated layer of the medallion architecture. Lesson 00-12.
Skew
Uneven data: one key or partition has far more rows than the others, so one task runs much longer. Lesson 00-05.
Source
The system where data is first created or stored before a pipeline reads it, such as an app's database, log files or sensors. Lesson 00-01.
Apache Spark
Open-source engine that processes large data in parallel across a cluster of machines. Databricks is built on it. Lesson 00-05.
Spark job
All the work Spark does to answer one action. Different from a Lakeflow job. Lesson 00-05.
Spark session
Your connection to Spark, available as spark in Databricks notebooks. Lesson 00-06.
Spark SQL
Spark's SQL engine: run SQL text over tables, views and DataFrames. Lesson 00-06.
SQL (Structured Query Language)
The standard language for asking tables questions and changing them. Works in almost every data tool, including Databricks. Lesson 00-01.
SQL warehouse
Compute that runs only SQL, built for queries and dashboards. Types: serverless, pro, classic. Lesson 00-09.
Stage
A set of tasks that run without moving data between executors. A shuffle starts a new stage. Lesson 00-05.
Streaming
Processing data continuously and incrementally as it arrives, usually in micro-batches. Lesson 00-04.
Table
Data organised in rows and named columns, like a tidy spreadsheet, that you can query with SQL. Its rows live in files; the table adds a name, schema and rules. Lessons 00-01, 00-02.
Table format
A way of organising data files plus metadata so they behave as a table with safe changes, such as Delta Lake or Iceberg. Lesson 00-03.
Task
One unit of Spark work: one stage on one partition, run by one core. Lesson 00-05.
Temporary view
A name for a DataFrame that SQL can use, valid only in the current Spark session. Stores no data. Lesson 00-06.
Three-level namespace
Unity Catalog naming: catalog.schema.object, like bike_shop.silver.rides. Lesson 00-11.
Time travel
Querying an older version of a Delta table with VERSION AS OF or TIMESTAMP AS OF. Lesson 00-10.
Transaction log
The _delta_log folder: an ordered record of every commit, listing which files make up each version. Lesson 00-10.
Transformation
A Spark step that defines new data from old, like filter or join. Lazy: it only adds to the plan. Lesson 00-05.
Trigger
The setting that decides when a streaming query runs its next micro-batch. Lesson 00-04.
Unity Catalog
Databricks' system for naming, organising and governing data and AI assets. Lesson 00-11.
VACUUM
A Delta command that deletes files no longer in the table and older than the retention period (7 days by default). Lesson 00-10.
Version (Delta)
A numbered snapshot of a Delta table, created by each commit, starting at 0. Lesson 00-10.
View
A saved query that behaves like a table but stores no data of its own. Lesson 00-11.
Volume
A Unity Catalog object for governed files, with paths like /Volumes/catalog/schema/volume/. Managed or external. Lessons 00-07, 00-11.
Workspace
A team's environment in the Databricks web app: notebooks, jobs, pipelines, dashboards and more. Lesson 00-08.
